# 网易云音乐功能集成可行性报告

> 结论：**技术上可行**。你的 BSP 接口与网易云固件完全兼容，`netease_client` / `audio_stream` 组件可直接移植。但有三个前提必须接受：① 电脑需常开 Node.js 中转服务；② 需要大中文字库，Flash 空间紧张需裁剪；③ 需要启用 LVGL 二维码组件。

***

## 1. 方案原理（为什么需要中转服务）

网易云音乐播放器**不直连网易云服务器**，而是采用「本地中转」架构：

```
设备(ESP32-C3) ──HTTP──> 电脑中转服务(Node.js, 局域网 18080) ──> 网易云 API
```

- 设备通过中转服务完成：设备注册 → 扫码登录 → 获取歌单/歌曲列表 → 获取歌曲播放 URL。

- 中转服务把歌曲 URL 转成本地局域网地址，设备再从电脑拉流 MP3 播放。

- **电脑不开中转服务，设备无法登录和播放**。你已确认愿意常开，此前提满足。

仓库地址：<https://github.com/PhoenixZHC/FoloToy-wyy-musicplayer>（V1.2.2，release 提供 Windows 便携包，无需装 Node.js）

## 2. 与你现有工程的兼容性

| 项       | 网易云固件                     | 你的工程                           | 兼容性          |
| ------- | ------------------------- | ------------------------------ | ------------ |
| 芯片      | ESP32-C3                  | ESP32-C3                       | ✅ 一致         |
| Flash   | 8MB 无 PSRAM               | 8MB 无 PSRAM                    | ✅ 一致         |
| 音频驱动    | `bsp_audio` (ES8311+I2S)  | `bsp_audio` (ES8311+I2S)       | ✅ 接口完全相同     |
| 显示      | LVGL 9.5                  | LVGL 9.5                       | ✅ 一致         |
| WiFi 配网 | 自研 SoftAP 配网页             | 已有 `study_wifi` 配网             | 🔧 可直接复用你现有的 |
| HTTP    | esp\_http\_client (HTTPS) | 已启用 HTTPS                      | ✅ 已具备        |
| 二维码     | LVGL 内置 `lv_qrcode`       | **未启用** `CONFIG_LV_USE_QRCODE` | ⚠️ 需打开开关     |

结论：音频、显示、网络三条链路全部复用现有代码，**不需要改 BSP**。

## 3. 需要移植/新增的组件

### 3.1 直接从仓库拷贝（改路径即可）

| 组件               | 文件                                                 | 行数     | 依赖                                        |
| ---------------- | -------------------------------------------------- | ------ | ----------------------------------------- |
| `netease_client` | `netease_client.c/h`                               | 809    | esp\_http\_client、json、mbedtls（你已有）       |
| `audio_stream`   | `audio_stream.c/h`                                 | 403    | esp\_http\_client、esp-tls、bsp\_audio（你已有） |
| 播放页面             | `netease_app.c/h` + `netease_app_logic.c/h`        | \~1244 | LVGL、netease\_client、audio\_stream        |
| UI 渲染            | `device_music_ui.c/h` + `device_music_ui_spec.c/h` | \~600  | LVGL                                      |

### 3.2 需要新增的第三方依赖

- **MP3 解码器**：`chmorgan/esp-libhelix-mp3`（组件管理器自动下载，\~100KB 编译产物）。`audio_stream` 通过 `mp3_decoder_helix.c` 薄封装调用。

- **二维码**：sdkconfig 打开 `CONFIG_LV_USE_QRCODE=y`（LVGL 内置，仅增加约 10KB）。

### 3.3 不需要移植的

- **配网页**：网易云固件自带 835 行 `wifi_provisioning_page.c`，但你已有 `study_wifi` 的 SoftAP+HTTP 配网，只需在现有配网页上**增加"中转地址 + 注册码"两个输入框**。

- **联网逻辑**：你已有 SNTP、WiFi 事件回调，可直接复用。

## 4. Flash 空间评估（最关键）

### 4.1 当前分区布局（8MB）

```
nvs        24KB
phy_init    4KB
factory    3MB   (app，0x10000)
cardid     16KB
voicepack 480KB  (语音包 .frc，实测 408KB)
recordings 3.18MB (录音，SPIFFS)
recovery   1MB   (BLE Recovery 固定)
```

### 4.2 新增代码量估算

- 网易云完整固件 app 编译产物能塞进 3MB factory 分区（参考其 release 全量 bin = 8MB，含全部 10 个字号字库）。

- 你的 factory 分区同样是 3MB。**代码本身（客户端+播放器+UI）约 +300KB，不影响当前 app**，前提是确认当前 app 已占用 < 2.7MB。

### 4.3 字库是真正的空间压力

| 字库来源                    | 大小                 | 说明                     |
| ----------------------- | ------------------ | ---------------------- |
| 你现有 `study_font`        | 203 码位 / 15px      | 仅 UI 固定文案，**不够显示任意歌名** |
| 网易云 `netease_ui_font_*` | 10 个字号，C 源码共 8.5MB | 覆盖 3827 汉字+符号，全放会爆分区   |

**必须裁剪**，建议方案：

- 只保留 **14px + 18px** 两个字号（对应列表/标题），去掉 8/9/10/12/13/17/22/24px。

- 用 `tools/generate_device_fonts.py` 重新生成**常用字子集**（歌名/歌手高频字，如 \~1000 字）而非全量 3827 字。

- 裁剪后字库预计 **0.8\~1.2MB**，可放入 `recordings` 分区压缩腾出的空间，或直接并入 app（app 静态区）。

### 4.4 recordings 分区压缩方案

如需给字库/音乐腾独立分区：

```
recordings   data spiffs 0x3D2000 0x1E0000   (2MB，录音上限从 ~74min 降为 ~45min)
music        data spiffs 0x5B2000 0x10A000   (1.06MB，字库或本地音乐)
```

若走在线播放（中转服务），**不需要**本地音乐分区，字库直接编译进 app 更省事。

## 5. RAM 评估（风险点）

ESP32-C3 无 PSRAM，RAM 约 400KB。`audio_stream` 运行时占用：

- MP3 输入缓冲 24KB（`heap_caps_malloc`）

- PCM 缓冲 4.6KB

- libhelix MP3 解码器堆 \~30-50KB（含帧缓冲）

- HTTP 缓冲 4KB

- 播放任务栈 8KB

合计约 **70-90KB 峰值**，与录音（16KB 栈）互斥使用（播放时不开录音），**可行性较高**，但需在真机验证堆余量（当前 app 已占用多少未知，需 `idf.py size` 实测）。

***

## 6. 集成步骤（按序）

1. 拷贝 `netease_client`、`audio_stream` 组件到 `components/`，在各自 `CMakeLists.txt` 加 `REQUIRES esp_http_client esp-tls json mbedtls bsp`。
2. sdkconfig 打开 `CONFIG_LV_USE_QRCODE=y`。
3. 在设置页（`study_ui.c` 的 `PAGE_SETTINGS`）新增"网易云音乐"入口行。
4. 新增 `netease_music_page.c`：扫码登录页 → 歌单列表页 → 歌曲列表页 → 播放页（复用 `device_music_ui.c` 渲染逻辑，改接入你的 LVGL 屏幕管理）。
5. 配网页增加"中转地址 + 注册码"输入，存入 NVS；复用 `study_wifi` 联网。
6. 字库：裁剪生成 `netease_ui_font_14.c` / `netease_ui_font_18.c` 常用字子集，加入编译。
7. 在 `main.c` 按键分发中，为网易云页面注册独立按键状态机（参照 `netease_app_logic.c`，其自带 191 行可测逻辑）。
8. 浅睡眠联动：`idle_sleep_task` 增加"播放中不休眠"判断（参考现有 `study_recorder_is_playing`）。

***

## 7. 风险与注意

| 风险          | 说明                       | 对策                          |
| ----------- | ------------------------ | --------------------------- |
| 中转服务必须常开    | 电脑关机/换网络设备即失效            | 已在前提中确认；Windows 便携包无需装 Node |
| 字库裁剪后歌名缺字   | 冷门歌名可能显示豆腐块              | 保留常用字子集 + 提供动态缺字补全机制（后续）    |
| RAM 峰值不足    | 播放+UI 同开可能堆紧张            | 真机 `idf.py size` / 堆统计实测后再定 |
| LVGL 页面管理冲突 | 网易云页面与你现有屏幕栈（首页/学习/设置）并存 | 独立 screen + 返回键接入现有返回逻辑     |
| 网易云 API 非官方 | 中转服务的 API 适配层为临时实现，可能失效  | 跟随上游仓库更新中转服务                |

***

## 8. 结论

- **能做**：组件即插即用，BSP 零改动，你已具备全部网络/显示/音频基础。

- **最实际的做法**：在线播放模式（中转服务），字库裁剪成 14/18px 常用字子集编译进 app，**不需要**动 recordings 分区，Flash 压力最小。

- **工作量**：约 5 个新文件（\~2500 行）+ 3 处小改动（sdkconfig、设置页入口、按键分发）。

- **决策点**：你确认愿意常开中转服务后，可以按第 6 节步骤开始实施。
