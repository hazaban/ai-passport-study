## 1. 计算机组成原理（硬件层）

### 1.1 处理器：ESP32-C3 RISC-V RV32IMC

- **ISA（指令集架构）**：RISC-V，`RV32IMC`：
  - `I` = 基础整数指令集（32 位）
  - `M` = 整数乘法/除法扩展（硬件 mul/div 指令，`m/div` 单条指令完成，不再靠软件循环）
  - `C` = 压缩指令扩展（16 位短指令，提高代码密度、节省 Flash）
- **架构特点**：
  - 单核，主频最高 **160MHz**（`CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ`）
  - 无 FPU（浮点单元）→ 这就是为何音频以**定点数**运算（Speex `FIXED_POINT`），浮点代价是软件模拟、极慢
  - RISC-V 的**通用寄存器 32 个**（x0-x31），`x0` 恒为 0，是编解码大量局部变量能放寄存器、省栈的原因之一
- **考研对应点**：
  - 指令系统：定长/变长指令、扩展位（IMC）
  - 运算器：ALU 做加减乘除、比较、逻辑运算
  - 寄存器：通用寄存器 + 程序计数器 PC
  - 编译器生成的代码就是「寄存器分配 + 访问内存装入/取出（Load/Store 架构）」~ 属<u>指令流水与数据通路</u>的最底层产出

### 1.2 存储层次与内存地址分配（408 重点，重头戏）

**经典存储层次**（自上而下容量↑、速度↓、价格↓）在此设备上均有对应：

```
CPU寄存器(RV32) → Cache(内置) → SRAM(400KB) → 内部Flash(4MB) → 外部…(无)
```

#### A. ESP32-C3 地址空间（RISC-V 32 位，4GB 可寻址）

| 地址段 | 内容 | 说明 |
|---|---|---|
| `0x3FC80000 ~` | **DRAM（数据段 .data/.bss/.rodata）** | 内核堆、任务栈、全局变量 |
| `0x4037C000 ~` | **IRAM（代码段/快速可执行内存）** | 部分快速程序 + 中断向量 |
| `0x42000000 ~` | **Flash 映射（MMU 只读窗）** | 只读代码/常量 `const`，CPU 直接读 Flash |
| `0x40000000` | ROM | 出厂 Boot ROM/BiOS |

> 注意：C 里写的**常量字符串和 `const` 表**（如科目名、Speex 码本表）被链接进 **Flash**，
> 通过地址 `0x4200…` 访问；而**可修改全局变量**放 **DRAM**。考研里「常量段 .rodata 放 ROM/Flash、变量段 .data/.bss 放 RAM」就是这个体现。

#### B. SPI Flash 分区表（`partitions.csv` —— 本项目真实地址）

这是「**地址空间分配**」最直观的例子。Flash 共 **4MB = 0x400000**。

```csv
# Name,      Type, SubType, Offset,    Size,     备注
nvs,         data, nvs,     0x9000,   0x6000,    系统参数键值(NVS)
phy_init,    data, phy,     0xf000,   0x1000,    电台校准参数
factory,     app,  factory, 0x10000,  0x300000,  固件 App 3MB
cardid,      data, nvs,     0x356000, 0x4000,    安装器固定
voicepack,   data, spiffs,  0x35A000, 0x78000,   语音包 SPIFFS 480KB
recordings,  data, spiffs,  0x3D2000, 0x32E000,  录音 SPIFFS ≈3.05MB
recovery,    app,  test,    0x700000, 0x100000,  OTA/恢复分区 1MB
```

**十六进制换算练习（计组常考）**：
- `factory` 大小 `0x300000` = 3×16^5 = **3MB**（start `0x10000`=64KB，`0x10000+0x300000=0x310000`）
- `recordings` 大小 `0x32E000` = 3×16^5 + 2×16^4 + 14×16^3 = 3,145,728 + 131,072 + 57,344 ≈ **3.05MB**
- 末尾 `recovery` 0x700000 + 0x100000 = 0x800000 = **8MB/页**（即 4MB Flash 上限）
- 分区类型 `Type`为 `data/app`，`SubType`为 `nvs/spiffs/factory/test`——是「分段的存储管理」雏形

**考研知识点**：
- 地址换算：十六进制 ↔ 十进制、容量（K/M/G=2^N）
- **分区 = 静态地址分区**：类似操作系统的「固定分区存储管理」，每个分区在编译期就用固定偏移/大小定死，地址不重叠（连续相邻布局）
- **SPIFFS 是"文件系统在分区之上"**：分区像是裸设备，SPIFFS 在其中管理文件块

#### C. SRAM 中的内存区段（链接脚本概念）

- `.text` 代码段 → Flash/IRAM
- `.rodata` 只读数据（码本、常量表） → Flash
- `.data` 已初始化全局变量 → DRAM
- `.bss` 未初始化全局变量（`.bss` 通常静态清零） → DRAM
- **堆（heap）**：`esp_get_free_heap_size()` 测量；动态 `malloc` 从这里取
- **栈（stack）**：每个任务独立。`uxTaskGetStackHighWaterMark()` 查看水位

> 关键考试概念：**堆向高地址增长、栈向低地址增长**，两者可相向逼近，冲突即栈溢出/堆损坏 → 本项目的崩溃根因（见 §6）。

### 1.3 外设与 I/O 方式

#### A. 编解码器 ES8311 + I2S（`bsp_audio.c`）

- **I2S 总线**（Inter-IC Sound）：专门传输数字音频的串行接口，有 **BCLK（位时钟）、WS（左右声道）、DIN/DOUT（数据）** 四线
- 配置摘录（真实代码）：
  ```c
  .sample_rate_hz = 16000,              // 采样率 16kHz
  .mclk_multiple = I2S_MCLK_MULTIPLE_256, // MCLK = 256×fs = 4.096MHz
  .data_bit_width = I2S_DATA_BIT_WIDTH_16BIT,  // 每样本 16 位
  .slot_mode = I2S_SLOT_MODE_STEREO,    // 双声道槽位
  .dma_desc_num = 6, .dma_frame_num = 240, // DMA 描述符/帧配置
  ```
- **MCLK 计算**（计组时钟知识点）：`MCLK = fs × 256 = 16000 × 256 = 4,096,000 Hz = 4.096 MHz`。这就是「分频器从系统主频得到外设时钟」——PLL/SYS 时钟 → 分频 → BCLK → WS
- 数据位宽 16、双声道：每次采样送 2×16bit，有效数据在低位。录音 `bsp_audio_read` 读到 int16 样本

**考研对应**：
- I/O 方式：**DMA（直接存储器存取）**——I2S 数据用 DMA 描述符在「外设 ↔ SRAM」搬移，不占用 CPU
- 串行 vs 并行传输、同步时钟（I2S 是带同步时钟的串行协议，区别于无时钟的 UART 异步）
- 时钟频率计算、分频器

#### B. 按键：三键共享一路 ADC（`bsp_button.c`）

- 上/下/确认三个按键通过**不同分压电阻**接到同一个 **ADC（模数转换）引脚**，按不同键 → 测到不同电压档位 → 判键
- **ADC 采样过程**：就体现「**量化（Quantization）+ 采样（Sampling）**」——模拟电压 → 离散数字值。多采样取平均抗噪
- **防抖（去抖动）**：机械按键按下/弹起有抖动，配合定时器判「稳定后的状态」，涉及**时序/状态机**
- 电压分压：`V_adc = V_ref × R2/(R1+R2)`，是**电阻串联分压**（属于「模拟电路/电子」基础，408 计组里较少，工程交叉）

#### C. 其他外设
- **I2C**（`bsp_i2c.c`）：两线（SCL/SDA），地址寻址总线，用于扫描外设（`i2c_scan`）——只有一根数据线所以是**半双工串行**
- **SPI**（LCD 屏幕，见 main.c 打印 `BSP_LCD_MOSI/SCLK/CS/DC/BL`）：四线全双工串行，CS 片选/SCLK 时钟/MOSI 数据/DC 数据或命令选择
- **GPIO**：背光（`bsp_display_backlight`）、PA 功放使能（`.pa_pin`）——最简单的「读/写引脚」

**考研比对**：常用总线串行协议对比
| 总线 | 线数 | 时钟 | 特点 |
|---|---|---|---|
| SPI | 4+（含CS/DC） | 同步 | 全双工、速率高 |
| I2C | 2 | 同步 | 地址寻址、半双工、多设备挂一条总线 |
| I2S | 4 | 同步 | 专传音频、有 LR 声道 |
| UART | 2 | **异步**（无时钟线） | 靠波特率对时、一对一 |

### 1.4 数据表示与编码（计组「数的表示」直接命中）

- **PCM（脉冲编码调制）**：模拟音频 → 定时采样 → 量化成整数。本项目用 `int16_t`（带符号 16 位定点 PCM）
  - **补码表示**：int16 负数用**补码**存储，`-1 = 0xFFFF`
  - 取值范围 `-32768 ~ +32767`，即 `[-2^15, 2^15-1]`
- **定点数 vs 浮点数**：无 FPU，Speex 用 `FIXED_POINT` 把所有实数运算改成定点 `Q` 格式（如 `Q15`，数值 = 整数 / 2^15），牺牲精度换速度
- **大小端（Endian）**：FRC 文件头用 `u16LE`（**小端 Little-Endian**）存包长——RISC-V 与 x86 同为小端，无需转换；若接大端（网络字节序）就需 `htons/ntohs`
- 位宽估算（考研常算）：
  - 8kHz × 16bit = **128kbps** 未压缩
  - Speex NB Q3 ≈ 0.75KB/s ≈ **6kbps**（≈21 倍压缩）
  - ADPCM 4KB/s ≈ **32kbps**

## 2. 操作系统（软件内核层）

系统 = **ESP-IDF（乐鑫出的 RTOS 应用框架）**，内核 = **FreeRTOS**。目录 `freertos/`。

### 2.1 任务（进程/线程概念）

- `xTaskCreate(函数, 名字, 栈大小, 参数, 优先级, 句柄)` 创建任务
- 本项目关键任务：
  - `rec_cap`（录音采集，栈 `CAP_STACK_BYTES`）
  - `rec_play`（回放，栈 `PLAY_STACK` = 16KB）
  - 按键任务、LVGL 刷新任务、`voice_worker`（语音命令）、WiFi 事件任务、诊断任务
- 每个任务一个**私有栈**，一个**task control block (TCB)**，保存寄存器上下文
- 考研对照：**进程/线程**的最小单位是任务，共享地址空间（同进程的多线程）——FreeRTOS 任务即「线程」，优先级抢占调度

### 2.2 进程/任务状态与调度

- 状态：**就绪 / 运行 / 阻塞**（睡眠 `vTaskDelay` / 等待队列 / 等待信号量）三种基本态
- 调度：**可抢占 + 优先级**调度（`REC_PRIO = 5`），更高优先级就绪立即抢占
- 时间片轮转：同优先级任务分时
- **优先级倒置/反转**问题在 RTOS 中有经典描述；`vTaskDelay(pdMS_TO_TICKS(30))` 就是让出 CPU 的阻塞

### 2.3 内存管理与崩溃分析（408 最相关的一节）

#### A. 内存分配方式对比
| 方式 | 位置 | 特点 | 本项目 |
|---|---|---|---|
| 静态（全局/数组） | `.bss/.data` | 编译期定死、不可变 | 码本、菜单数组、`int16_t buf[512]` |
| 栈分配 | 任务栈 | 自动回收、快、栈成帧 | 局部变量 `int16_t buf[STUDY_FRAME_SAMPLES]` |
| 堆分配 | 堆 | 灵活、需 free、会碎片化 | `malloc(64)` 录路径、编码器 `speex_encoder_init` |

#### B. 堆碎片化（fragmentation）
- `esp_get_free_heap_size()` = 总计空闲，`heap_caps_get_largest_free_block()` = **最大连续空闲块**
- 二者的差就是「**碎片**」：总和够，但连续的块不够 → `malloc/任务创建`失败
- **本项目经典问题**：空闲堆约 33KB、最大连续块仅 16KB。而 `xTaskCreate(rec_cap, 32KB)` 需要一个 **≥32KB 的连续块**，根本凑不出来 → `pdFAIL`

#### C. 栈溢出（Stack Overflow）
- 栈向下增长（高地址→低地址），局部数组越界 / 递归过深 → 覆盖相邻内存
- 捕获手段：`uxTaskGetStackHighWaterMark()` = **剩余最少栈水位**（HWM 低 = 栈快满）
- Speex 编码器在栈上开大数组（如 MDCT 临时表），NB ≈ 3KB 峰值栈、WB 更大 → 栈不够→溢出→PANIC

### 2.4 同步与进程互斥

- **互斥锁 / 信号量**：LVGL 线程安全用「锁」——`bsp_lvgl_lock(超时)/unlock`，因为按键、WiFi、事件都在别的任务，操作 UI 必须加锁（临界区）
- **二进制/计数信号量**、**互斥量 MUTEX（带优先级继承）**是常考对象
- 本项目事件循环用**环形队列**实现（不仅是 OS 队列，见 §3）：`push_evt` 生产、`poll_evt` 消费

### 2.5 竞争条件与原子性（并发编程考点）

- `volatile` 关键字：`static volatile bool s_recording`——防止编译器缓存到寄存器，保证每次从内存读（多任务共享标志位）
- 但有 **non-atomic** 问题：`s_evt_w` 读-改-写不是原子，若被 ISR 打断可能丢事件 → 用简单环形缓冲 + 快速读改（本项目规模下足够）
- 「忙门闩」`study_recorder_active()` 检查 `recording || playing` 再决定是否进入，防止录音/回放/语音互抢 codec

### 2.6 死锁

- 条件：互斥、占有并等待、不可剥夺、循环等待（四必要条件，408 必背）
- 本项目规避：`bsp_lvgl_lock(超时)` **带超时**，不会无限等待；且加锁-操作-解锁在最短临界区内完成，避免嵌套锁等待

### 2.7 复位与崩溃恢复（操作系统「异常处理」）

- `esp_reset_reason()` 返回复位原因：`ESP_RST_PANIC`（内核异常重启）/ `ESP_RST_POWERON`（上电）/ `ESP_RST_SW`（软复位）
- **PANIC 是什么**：CPU 触发异常（非法地址访问、未对齐、指令错误）→ 内核捕获 → 寄存器转储 → 重启。这就是「上次是 PANIC」的含义
- 录音崩溃后：
  - 临时文件 `ACTIVE.TMP` 残留 → `study_recorder_init` 做**崩溃恢复**（清残留、校验序号）
  - 序号 `seq` 存 **NVS**，断电不丢 → 「**持久化 + 崩溃一致性**」

### 2.8 文件系统 SPIFFS（`esp_spiffs.h`）

- **SPIFFS**：小容量嵌入式闪存文件系统，在 `recordings` / `voicepack` 分区上挂载
- 操作：`fopen/fwrite/rename/opendir/readdir`（标准 POSIX 文件 API 抽象）
- 关键点（OS「文件系统」章节）：
  - **命名**：`/rec/R%07u.FRC`（7 位补零序号 → 字典序=时间序）
  - **rename 原子性**：`rename(ACTIVE.TMP, path)` 作为"提交点"，中断/崩溃前文件不完整，改名后才成正式文件（**原子操作保证一致性**）
  - 目录项：`dirent` 遍历 → 扫描录音列表
  - 容量：`study_recorder_free_kb()` 剩余空间，写满前拒绝（`<100KB` 打住）——「**存储配额/提前防溢出**」

### 2.9 NVS 键值存储（`nvs.h`）

- 类似**小型数据库/键-值表**，按**命名空间**隔离：`nvs_open("recorder"/"wifi"/"tasks"/"config", ...)`
- API：`nvs_get_u32` / `nvs_set_u32` / `nvs_commit`（**提交才落盘**）
- 考研对照：
  - 「增删改查 + 命名空间」≈ 关系数据库的「表 + 主键」
  - `nvs_commit` = **事务提交**（写入有原子保证，断电不丢半条）
  - 键值对其实底层是「哈希/B+ 相关索引」在 Flash 上的组织（FRC 文件里也体现块组织）

### 2.10 低功耗与唤醒（可选，`demo_low_power.c` / `main.c`）

- `esp_sleep_get_wakeup_cause()`——休眠/唤醒源；电源管理、深度睡眠、定时器唤醒
- 考研「操作系统」外设管理、中断唤醒的体现

## 3. 数据结构与算法

### 3.1 环形缓冲区（Circular Buffer / Ring Queue）—— 事件队列

**真实代码**（`study_recorder.c`）：
```c
#define EVT_N 8
static volatile int s_evt[EVT_N], s_evt_w = 0, s_evt_r = 0;  // 写指针/读指针
static void push_evt(study_rec_evt_t e) {
    int w = s_evt_w;
    s_evt[w] = (int)e;
    w = (w + 1) % EVT_N;              // 取模循环
    if (w == s_evt_r) s_evt_r = (s_evt_r + 1) % EVT_N; // 满则覆盖最旧
    s_evt_w = w;
}
study_rec_evt_t study_recorder_poll_evt(void) {
    if (s_evt_r == s_evt_w) return REC_EVT_NONE;  // 空
    int e = s_evt[s_evt_r]; s_evt_r = (s_evt_r + 1) % EVT_N;
    return (study_rec_evt_t)e;
}
```
- **FIFO（先进先出）** 队列，固定容量 `EVT_N=8`，头尾指针环形推进
- 判空：`r==w`；判满；取模回绕避免数组越界
- **生产-消费模式**：录音任务 push（生产），UI 轮询 poll（消费）
- 考研对应：**循环队列**的队满条件 `(rear+1)%size==front`；其中一方空出一个不用是谁（占位法）经典变体。这里是"满则覆盖最旧"（可变丢弃策略）

> 诊断日志 `study_diag` 同样用环形缓冲保存崩溃前采样（`s_ring[s_w]`），保证覆盖写不丢最近数据。

### 3.2 顺序表 / 定长数组（任务列表）

- 任务模型用定长数组保存：`TASK_MAX_COUNT = 256`，`title[40]`——**顺序存储结构**
- `study_task_t` 是**结构体**（记录任务属性：id、标题、科目、子类、时间、重复、完成态、时间戳）
- 固定上限因为嵌入式内存有限 → 「**预分配 / 容量约束**」

### 3.3 位图（Bitmap）—— 重复周期与完成记录

- `repeat` 字段：`STUDY_REPEAT_CUSTOM` 用 `bit0=周一 … bit6=周日` 的**7 位位图**表示周期性
- 调度器的「今日已响铃 fire 位图」：用位标记避免重复提醒
- 优点：**一个字节存 7 天信息**，空间效率高，`&`/`|` 位运算判断——位图是数据压缩 + 集合表示的经典考点

### 3.4 存储抽象层 vtable（函数指针表）—— 多态/接口

**真实代码**（`study_task.h`）：
```c
typedef struct {
    int (*save_task)(const study_task_t *t);
    int (*load_task)(int id, study_task_t *out);
    int (*delete_task)(int id);
    ...
} study_task_store_t;   // 一组函数指针 = 一个"抽象接口"
```
- **函数指针数组/结构体 = 虚函数表（vtable）**：C 语言实现「多态」的经典手法
- 同一套业务代码可对接：`study_task_nvs.c`（真机存 NVS）或 **内存 mock**（`tests/test_study_task.c` 宿主测试）
- 考研对应：
  - **函数指针**与间接调用（编译原理：调用约定、地址间接跳转）
  - **抽象数据类型 ADT / 模块化**；策略/模板方法设计思想在系统设计课里的体现

### 3.5 结构体与内存对齐（Alignment）

- 处理器访问对齐数据更快/必须对齐；编译器在结构体字段间**插入 padding**
- `study_task_t` 里 `int hour; int8_t minute;` 等，`#pragma pack`/字段顺序影响 sizeof
- 嵌入式常**按字段大小排序**减少 padding 省内存——考研「结构体字节数计算」题目
- 32 位对齐：`0x…000`/`/4` 整除；未对齐地址 → RISC-V 可能异常（PANIC 一源）

### 3.6 排序（任务列表排序）

- `study_task_list_today`: 按「有时间的按时间升序在前、无时间的在后」排序
- 典型实现基于比较（插入/选择/快排）；`o->per_category` 分类统计是**计数**思想

### 3.7 字符串与格式化

- `snprintf(path, cap, "/rec/R%07lu.FRC", seq)`——**格式化输出**（编译原理里的 printf 可变参数）
- 补零宽域 `%07u` 保证文件名可字典序排序
- 字符串以 `\0` 结尾（C 字符串）、`strlen/strcpy` 及其**缓冲区溢出**风险——「字符串 = 指针 + 长度约定」考点

### 3.8 二叉/多路搜索（设计体现）

- 科目 → 子分类 → 任务：**层次化（树形）**分类结构
- 查找下一个提醒任务：遍历 + 条件过滤（线性）→ 空闲时可换「最小堆 / 有序表」优化——讲解为什么当前规模用遍历即可

## 4. 计算机网络（无线通信层）

### 4.1 网络分层（五层模型·408 核心）

本项目网络栈由 **LwIP（轻量 TCP/IP 协议栈）**提供，自上而下：

```
应用层： HTTP 网页配网 / SNTP / DHCP 客户端
传输层： TCP（HTTP）、UDP（SNTP、DHCP）
网络层： IP、ICMP
数据链路层： WiFi MAC / 以太网帧
物理层：  802.11 无线射频
```

### 4.2 WiFi：STA 与 SoftAP（802.11）

`study_wifi.h` 状态机：`IDLE → AP_CONFIG → CONNECTING → CONNECTED / FAILED`（一个有**状态转移**的应用协议例子）

- **STA（站点）模式**：连家庭路由器，拿到 IP
- **SoftAP（软热点）模式**：设备自己开热点 `ssid 前缀 + 后4位MAC`，密码 `"liyufan408"`（**WPA2 ≥8 字符**）
- 无键盘设备配网方案：**手机连热点 + 浏览器打开 `http://192.168.4.1` 填账号密码**——经典「**网页配网 / WebProvision**」架构

### 4.3 IP 寻址 & DHCP

- SoftAP 网段 `192.168.4.x`，网关 `192.168.4.1`
- **DHCP**：设备连上路由器后自动向 `255.255.255.255`（广播）请求，路由器分配 IP/网关/DNS——「**动态主机配置协议**，UDP 67/68」
- 网络地址 `192.168.4.0/24`：主机位 8 位 → 可用 256；`.1` 固定给网关/AP→网关 IP 名分

### 4.4 传输层 TCP / UDP

- **TCP**（HTTP 用）：可靠、面向连接、三次握手/四次挥手、序号与确认、流量/拥塞控制——文档配网 POST 用 TCP
- **UDP**（SNTP/DHCP 用）：无连接、不可靠、开销小
- 对比表常在 408 网络大题出现；本项目实测两种都在用

### 4.5 HTTP 网页配网

- 设备起 HTTP 服务（端口 `STUDY_WIFI_AP_PORT=80`），浏览器 GET 页面、POST `/submit` 表单提交 WiFi
- 涉及：**HTTP 请求报文**（方法/URL/头部/正文）、**响应码**、`application/x-www-form-urlencoded`
- 设备收到 → 存 NVS → 切 STA

### 4.6 DNS 与 SNTP 校时

- **DNS**：域名解析 `域名 → IP`（若配网填域名才需要，走 UDP 53）
- **SNTP**（简单网络时间协议, `ntp` date）：设备从时间服务器同步时钟，`main.c` 相关；`SNTP over UDP`——这就是设备能显示「几点」的来源（Memory: RTC 钟 + 网络校时）

### 4.7 无线安全

- **WPA2-PSK** 加密（`WIFI_AUTH_WPA2_PSK`）；密码长度约束 `≥8` 是协议强制
- SSID 广播、MAC 过滤、握手（PSK → PTK）——属于「网络安全/密码学」交叉考点

## 5. 其他学科 / 交叉工程

### 5.1 数字信号处理（DSP，本质是「信号与系统 + 计组」交叉）

本项目最「硬核」的部分，也是崩溃重灾区。

#### A. 采样定理（奈奎斯特）
- 采样率必须 **> 2× 信号最高频率** 才能无失真还原
- 8kHz 采样 → 理论上限 4kHz（人声主要能量区）；16kHz → 8kHz，音质更好但数据量翻倍 → 内存压力翻倍
- `STUDY_FRAME_SAMPLES = fs × 帧长 = 8000 × 0.02 = 160`（20ms 帧）——20ms 是语音编码常用帧长（延迟与效率平衡）

#### B. PCM → 压缩编码（三种可选，head `study_audio_codec.h`）
| 编码 | 类型 | 码率 | 内存/栈 | 原理简述 |
|---|---|---|---|---|
| **Speex NB** | CELP（码激励线性预测） | ~0.75KB/s(6kbps) | 小 | 线性预测 + 激励码本 + LP 系数量化 |
| Speex WB | 16k 次带 CELP(QMF分频+FFT) | ~1.32KB/s | 大 | PSY 模型 + 二次带，重、吃内存 |
| **Opus SILK** | 线性预测 + MDCT | ~6kbps | 大(32KB栈) | 分析滤波器 + 矢量量化 |
| **IMA-ADPCM** | 差分脉冲编码 | 4KB/s(32kbps) | 极小 | 只存差值+自适应步长，Y话 |

- **Speex = 线性预测编码（LPC）**：用历史样本预测当前 → 只传预测误差和系数（**预测编码**考点：压缩靠去冗余）
- **CELP**：激励用 **码本（codebook）** 搜索，再经 LPC 滤波器合成——`exc_*.c` 表格就是码本（**数组/查表**的存储）
- **ADPCM**：差分量化（Differential PCM）+ 自适应步长调整——`pred + idx + 80B`，`2+1+1+80=84B/帧` 的固定负载换算（`STUDY_FRC_PAYLOAD_LEN`）
- **定点 FFT/DCT**：`kiss_fft`、`smallft`、MDCT——**DFT/FFT** 频谱分析应用（计组：旋转因子表 = 查表加速；DSP 核心）

#### C. 帧容器 FRC 格式（数据结构 + 文件组织）
```
FRC2: magic(4B) + frames(4B) + codec_id(1B) + 帧流
  每帧 = u16LE(len) + payload(len)   ← 变长帧（自描述）
```
- 头部自描述 `codec_id` → 读取端自动选择解码器——「**自描述/多态文件格式**」；向后兼容（FRC1/FRC2）
- 位流 `SpeexBits` 是 **变长位写入（bitstream）**——把压缩后的非整字节比特打包成流，体现「位流拼接/解析」考点

### 5.2 编译原理与构建（CMake + GCC for RISC-V）

- **预处理宏**：`#define CAP_STACK_BYTES …`、`#if defined(STUDY_REC_SPEEX)` 编译期条件编译 → 三种编码只编一种，**垃圾代码不被链接**
- **CMake/IDF 构建**：`idf_component_register(SRCS …)` 指定源文件（如 speex 组件只列 NB 需要的 `.c`，**不列** `modes_wb.c / sb_celp.c / fftwrap.c`——从物理上砍掉 WB 代码，避免占用 Flash/RAM）
- **编译选项**：
  - `-ffunction-sections -fdata-sections` + 链接 `--gc-sections`：把每个函数/数据放独立节，链接时**丢弃未引用者**（裁剪 WB 的 `const` 码本表）
  - `-Wno-*` 关告警；`FIXED_POINT`/`USE_SMALLFT`/`USE_ALLOCA` 这些宏是**条件编译**的精髓
- **USE_ALLOCA 的含义**（重要，影响崩溃）：转为用栈临时内存而非**堆一次性大块**——见 §6
- 链接：分区偏移在**链接脚本/分区表**约束，`FoloToy-AI-Passport.bin` 等产物是**链接输出**；`bootloader.bin` 是引导程序

### 5.3 软件工程与测试

- **分层/解耦**：纯逻辑层与硬件层分离——`study_scheduler`「不依赖 FreeRTOS/LVGL，可在 Linux 宿主测试」
- **宿主测试**：`tests/`、`host_test/` 在主机上编译运行（mock 掉硬件），`test_rec/test_raw` 跑编解码回归
- **存储层 vtable 注入假存储**（`study_task_nvs.c` vs 内存 mock）——**测试替身（Test Double）/依赖注入**
- **CI/CD**：`.github/workflows/ci-build.yml` 自动构建；`dependencies.lock` 锁依赖版本（可复现构建）
- 崩溃后「诊断日志 WiFi 导出」——**可观测性/运维闭环**

### 5.4 数据库 / 一致性

- NVS ≈ 微型**键值数据库**（命名空间=表，键=主键）
- `nvs_commit` = **事务提交**，断电一致性
- FRC/SPIFFS：`rename` 原子改名实现「最后一步才可见」——**文件系统事务**的简化版

### 5.5 GUI（LVGL）

- LVGL 是嵌入式图形库：对象树、样式系统、事件回调、**帧缓冲渲染**（LCD 屏幕是像素缓冲）
- **锁**：所有任务改 UI 都要 `lvgl_lock`——多线程访问 GUI 的**临界区**
- 屏幕 `224x46` 等卡片坐标——**坐标系/布局算法**

## 6. 重点案例深度分析

### 6.1 「16kHz Speex 宽带录音内存崩溃」根因（本项目最值得复盘的问题）

**现象链**：16kHz 版本 → 录第二条「rec error」→ 超 10 秒闪退白屏 → 多段后闪退。

**逐步归因（结合 §1.2/§2.3）**：

1. **内存需求翻倍**：
   - 采样率 8k→16k：每帧样本 `160 → 320`（大一倍），缓冲/位流翻倍
   - 编码器 WB 比 NB 重：**MDCT/FFT/心理声学模型**要大量栈与堆空间
2. **堆连续块不足触发失败**：
   - 空闲堆 ≈ 33KB，**最大连续块** ≈ 16KB（碎片化）
   - `xTaskCreate(rec_cap, 32KB)`：任务栈需要 **≥32KB 连续内存** → 最大连续块才 16KB → `pdFAIL`
   - 即便任务创建成功，剩余堆装不下 WB 编码器状态 → `speex_encoder_init` 返回 NULL
   - 这一路分配失败 → 报「rec error」/ `ESP_RST_PANIC`
3. **为什么"几秒短录音可以、超 10 秒不行"**：
   - 短录音前堆还够（被上次释放过）；长录音时间累积、编码器内部缓冲/堆随帧增长、旧块未及时回收 → 在某一刻内存耗尽/碎片加剧 → 分配失败
   - 任务栈若编码峰值超过分配的小栈 → **栈溢出** → 覆盖 TCB/邻居内存 → PANIC
   - 每次 PANIC 重启后堆又被重新初始化，所以"看起来还能录短条"，但累计分配/碎片问题反复 → 越来越不稳
4. **诊断日志证据**：`reset_reason=PANIC`；`heap≈33-37KB, maxblk≈16-26KB` → 空余最大连续块都不足 32KB，录音启动必然失败。

**工程解法（也是 408 知识应用）**：
- 回退到 **8kHz Speex NB**（改 `STUDY_REC_SPEEX` + `speex_nb_mode` + 采样 `8000/160`）
- 减小 `CAP_STACK_BYTES`（16KB 而非 32KB）
- `-ffunction-sections/-gc-sections` 裁剪 WB 码本表（减少 `.rodata` 占 Flash/加载）
- 编码前 `esp_get_free_heap_size()<8000` 门槛拒绝；录音前 `study_recorder_free_kb()<100KB` 拒绝——**防御式容量检查**
- 任务创建失败、编码失败全部打日志返回（失败路径要兜底）

> 一句话考点总结：**内存是"总和 vs 连续块"两个维度；栈/堆是嵌入式两大内存压力源；编译期裁剪可以减少内存占用；失败路径必须显式处理。**

### 6.2 按键「幽灵点击」= ADC 噪声 + 物理抖动

- 三个键共用 ADC，**按压力过程电压穿过相邻档位窗口** → 一次物理按键额外触发"相反方向键"单击
- WiFi 射频噪声让电压在**单键窗口**内抖动 → 同键快速重复单击
- 解法（体现多学科）：
  - **硬件/物理**：多采样取平均（`bsp_button.c` 4 次平均）抑制随机噪声
  - **算法/时序**：延长消抖时间、用**时间窗口**（如 250ms）过滤同键/异键快速重复 → 「**边沿/事件去抖状态机**」
- 联系：信号处理（低通滤波思想）+ 嵌入式事件机制 + 竞态预防

### 6.3 WiFi 射频噪声 = 电磁兼容（EMC）

- 高频无线信号通过**天线/走线耦合**进 ADC/电源 → 干扰采样
- 应对：软件数字滤波 + 抑制窗口 + 硬件布局/屏蔽
- 考研交叉：物理层噪声、信噪比 SNR 概念、数字滤波抗噪（DSP）
